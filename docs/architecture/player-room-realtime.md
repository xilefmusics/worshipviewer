# Player Room realtime architecture

HTTP performs discovery, creation, invitation exchange, role claims, reconnect-ticket exchange, explicit closing, and scoped media reads. A server-authoritative WebSocket carries presence and shared-state commands.

SurrealDB is authoritative for room state; process memory contains active socket broadcasters only. The base content snapshot is captured at room creation, while promoted queue songs are appended as immutable snapshots. Queue state and other mutable fields update together with the room revision. A room's `closed_at` field is its only lifetime flag. Heartbeats update participant presence leases; they never end a room. Commands are checked against the room-local participant represented by their one-use connection ticket, and host commands compare that participant's authenticated `user_id` with the durable room host account. Queue additions use authenticated HTTP authorization to re-check the adding user's library access before snapshotting the song; after that, the room's scoped media authorization serves the captured content to every participant. The room host and AV host therefore remain separate even when both participants use the same account.

The client renders a complete snapshot before accepting incremental state. It tracks the latest revision, ignores older data, and requests a fresh snapshot after a gap. Reconnect uses a participant resume credential with bounded exponential backoff. Existing non-room AV output continues using the browser-local `BroadcastChannel` path.

There are no scheduled backend room jobs. Participant expiry is evaluated by the request or socket event that touches a room; room closure is explicit and online-only. Same-instance sockets receive deltas immediately through the process-local broadcaster. With multiple Cloud Run instances, SurrealDB remains the shared authority and a socket on another instance detects a revision change on its next active-room heartbeat and requests one fresh snapshot. Shared pub/sub or a database change feed remains an optional latency improvement for immediate cross-instance fan-out.

Queue additions, host reorder/removal, and promotion use the room revision for optimistic concurrency. Additions publish a `queue_updated` delta. Promotion publishes a complete snapshot because it changes both queue state and player content/current item.
